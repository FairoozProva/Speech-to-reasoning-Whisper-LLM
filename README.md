# Speech-to-Reasoning Pipeline with Whisper and a Quantized LLM

Ask a question out loud and get a written, step-by-step answer. Whisper turns the audio into text, and a 4-bit Llama model that I fine-tuned reads that text and reasons through it. Everything runs in one Google Colab notebook on a free Tesla T4.

This is Task 4 of my Generative AI internship.

## How it works

```
Audio (.mp3 / .mp4 / .wav)
  -> decode to 16 kHz mono (ffmpeg + librosa)
  -> Whisper-small, fp16, batched          (speech to text)
  -> Whisper removed from the GPU
  -> Llama-3.2-3B-Instruct, Unsloth 4-bit + LoRA adapter   (reasoning)
  -> answer
```

| Part | Choice |
|---|---|
| Speech recognition | `openai/whisper-small`, fp16, batch size 8, 30 s chunks |
| Reasoning model | `unsloth/Llama-3.2-3B-Instruct-unsloth-bnb-4bit` |
| Fine-tuning | QLoRA, rank 16, 24.3M trainable parameters (0.75%) |
| Training data | First 1,000 rows of GSM8K, 100 steps |
| Hardware | Colab Tesla T4 (14.56 GB) |

## What the notebook covers

- Encoding: any audio file is converted to 16 kHz mono before Whisper sees it.
- Batching: several audio files go through Whisper together, and the LLM answers its prompts as one left-padded batch.
- Memory: Whisper is deleted and the CUDA cache cleared before the LLM runs, so only one model sits on the GPU at a time.
- Fine-tuning: the adapter is trained, saved, reloaded from disk and used for the final demo.
- Demo: `speech_to_answer()` takes audio paths and prints what was heard and what the model answered.

## Results

| Measure | Value |
|---|---|
| Whisper loaded | 0.46 GB |
| 4-bit LLM + LoRA | 2.29 GB |
| Training | 3.3 min, 7.98 GB peak |
| Full two-query demo | 16.5 s, 4.26 GB peak |
| Training loss | 1.97 at step 10, 0.97 at step 100 (lowest 0.89 at step 70) |

Sample run:

- Spoken: "If a train travels at 60 kilometers per hour for two and a half hours, how far does it go?" Answer: 150 kilometers.
- Spoken: "What is the capital of Bangladesh and why is it important?" Answer: Dhaka, with its role as the economic, cultural and administrative center.

## Run it

1. Open `Intern_task4.ipynb` in Google Colab.
2. Set the runtime to **T4 GPU** (Runtime, then Change runtime type).
3. Upload your own recording as `q2.mp4` before the ffmpeg cell, or skip that cell and the second test file. The first test audio is generated by the notebook itself.
4. Run the cells from top to bottom.

## Limitations

- The fine-tuning is small, and I did not benchmark accuracy on the GSM8K test set, so I don't claim a measured accuracy gain. The tuned model mostly changes answer style.
- A 3B model can get facts wrong on open questions.
- Whisper's chunked mode prints an "experimental" warning for long recordings.
